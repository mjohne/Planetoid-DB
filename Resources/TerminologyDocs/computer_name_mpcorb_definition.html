Orbit Determination Provenance • MPCORB Reference

Computer Name (Scomp, Columns 151–160)

Orbit-Determination Software Pipeline, JPL Solution Identifier & Orbitalist Provenance in MPCORB.DAT

1. Formal Definition

In the Minor Planet Center Orbit Database (MPCORB), the Computer Name (Scomp, officially specified by the IAU Minor Planet Center as the “Computer name” field in columns 151–160, 1-indexed, formatted as FORTRAN A10, with 0-based character slice [150..160]) is a 10-character ASCII provenance string identifying the orbit-determination software pipeline, dynamical force model, and/or institutional/human orbit computer responsible for computing the osculating orbital elements in that MPCORB.DAT record:

Scomp ≡ Record[150 : 160] ∈ ΣASCII10,    Provenance(O) = ⟨ Sref, Scomp, Fflags ⟩ (Eq. 1)

where:

  • Scomp occupies character columns 151–160 (10 bytes, padded with trailing spaces), situated immediately after the 9-character Reference field (columns 142–150, e.g., MPO891234 or E2025-V12 citing the Minor Planet Circular / Orbit Supplement publication) and separated by a single blank space (column 161) from the 4-hexdigit orbital-type flags (columns 162–165).
  • Historically, in astrometry and celestial mechanics, a “computer” referred to the human mathematician or staff astronomer performing least-squares differential orbit corrections (such as Williams, Marsden, Nakano, Bowell, Goffin, or Giorgini). In modern automated MPC and JPL Horizons / SSD pipelines, Scomp records either the automated integration/fitting engine (e.g., MPCLINUX, MPCW, ORBFIT, JPL 48, JPL 218) or the assigned orbitalist / solution identifier.
  • Together with the Reference (Sref, columns 142–150) and the 4-Hexdigit Flags (Fflags, columns 162–165, specifically bit 0x1000 indicating a planetary-perturbed solution vs. unperturbed two-body solution), Scomp establishes full computational provenance for the osculating state vector (M0, ω, Ω, i, e, n, a).

Preceded by the planetary perturber indicators (columns 143–149) and followed by the 4-hexdigit flags (columns 162–165), Scomp distinguishes automated MPC cluster integrations, JPL SSD/Horizons solution numbers, and named orbitalists.

2. Taxonomic Classification of MPCORB.DAT Computer Names

Across the >1.4 million minor planet records in MPCORB.DAT, entries in columns 151–160 fall into four well-defined institutional and algorithmic categories:

Category Representative Values (Cols 151–160) Institutional Origin & Algorithmic Meaning
Automated MPC Batch Systems MPCLINUX, MPCW, MPC, AutoMPC Automated orbit determination software running on Minor Planet Center servers (historically VAX/VMS, subsequently Linux clusters MPCLINUX) performing batch differential corrections for newly linked or updated minor planets.
JPL SSD / Horizons Solutions JPL 48, JPL 218, JPL K241/2, JPL E2023-1 High-precision numerical integrations imported from NASA/JPL Solar System Dynamics (SSD) / Horizons (typically for numbered planets, NEAs, PHAs, and radar targets), where the numeric/alphanumeric suffix denotes the JPL orbit solution version.
External Orbit Software ORBFIT, FIND_ORB, Astdys Orbits computed using specialized third-party celestial mechanics packages—such as the Pisa/NEODyS OrbFit consortium package or Bill Gray's Find_Orb—and ingested into the MPC catalog.
Human Orbitalists / Staff Williams, Marsden, Nakano, Spahr, Rudenko, Veres, Goffin, Bowell Surname (truncated to 10 characters if longer) of the MPC staff astronomer or external celestial mechanician who executed or validated the orbit fit and multi-apparition linkage (e.g., G. V. Williams, B. G. Marsden, S. Nakano, T. B. Spahr, M. Rudenko).

3. Fixed-Column Context & Parsing Specifications

Because MPCORB.DAT uses a strict fixed-width ASCII record structure without delimiters, whitespace inside columns 151–160 (such as the space in JPL 48) is significant and must not be split by whitespace tokenization:

  • Exact Column Boundaries:
    • 1-indexed FORTRAN format: Columns 151..160 (A10), preceded by column 150 (blank separator after Precise perturbers in columns 147..149) and followed by column 161 (blank separator before 4-hexdigit flags in columns 162..165).
    • 0-indexed C# / Python slice: line.AsSpan(150, 10).Trim() (C#) or line[150:160].strip() (Python).
  • Distinction from Reference (Columns 108–116): In MPCORB.DAT, columns 108..116 store the bibliographic publication code (e.g., MPO891234 for Minor Planet Orbit Supplement or MPC 41234 for Minor Planet Circulars), whereas columns 151..160 identify the agent or software that computed the orbit.
  • Coupling with Perturber Flags (Columns 143–149): When Scomp begins with JPL or equals MPCLINUX on multi-opposition objects, columns 143..145 (coarse perturbers, e.g., M-v = Mercury through Neptune) and 147..149 (precise perturbers, e.g., 30h or 3Eh including major asteroids Ceres, Pallas, Vesta) specify the exact N-body force model used by that computer.

4. Worked Examples from MPCORB.DAT

The following two records from MPCORB.DAT (epoch K25BL = 2025 Nov 21.0 TT = JD 2461000.5) illustrate how columns 151–160 appear in context alongside the perturber indicators (columns 143–149) and 4-hexdigit flags (columns 162–165):

Example 1: (1) Ceres — JPL SSD Solution Identifier (JPL 48)

Excerpt of MPCORB.DAT columns 138–202 for 00001: 

... 0.61 M-v 30h JPL 48     1000   (1) Ceres                  20251018
  • Extracted Computer Name (Cols 151–160): "JPL 48 " → trimmed: JPL 48.
  • Provenance Interpretation: Indicates that the osculating elements for (1) Ceres were computed by the NASA/JPL Solar System Dynamics orbit-determination pipeline (solution #48), incorporating planetary perturbers Mercury–Neptune (M-v) plus massive main-belt perturbers (30h), yielding an astrometric RMS residual of 0.61″.

Example 2: Automated MPC Cluster Integration (MPCLINUX)

Excerpt of MPCORB.DAT columns 138–202 for a multi-opposition main-belt asteroid: 

... 0.54 M-v 38k MPCLINUX   0000   (123456) 2000 WY12         20250904
  • Extracted Computer Name (Cols 151–160): "MPCLINUX " → trimmed: MPCLINUX.
  • Provenance Interpretation: Indicates an automated differential orbit correction executed by the Minor Planet Center's Linux-based production pipeline (MPCLINUX) using full planetary perturbations (M-v, 38k) with an astrometric RMS residual of 0.54″.
